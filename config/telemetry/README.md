# Durable telemetry runtime

Python 3.11+ standard library only. Install/copy `lme_telemetry` under the service working directory; run `python3 -m lme_telemetry --config /etc/lme/telemetry.json serve` and a separate `worker` process. `work-once` performs bounded delivery, `status` prints aggregate JSON, `gc` purges expired verified archive, and `ingest-file PATH` reads canonical newline-delimited records with atomic SQLite file-generation offsets. Run as one dedicated user with a private writable spool directory. Use a local filesystem supporting SQLite WAL and fsync, not NFS.

`runtime.example.json` is the exact configuration schema. Destinations select new admissions only. Keep removed sink adapters/credentials configured until their existing obligations drain. Changing a sink's address/index must retain access to already admitted events; do not reuse destination names for unrelated stores. Workers serialize per spool via a file lock; admission serializes atomically in SQLite. Configure lifecycle supervision to restart the worker and ingress independently. Changes to the JSON configuration apply on process restart.

Ingress: authenticated `POST /v1/logs`, `Content-Type: application/json`, with exactly one of `records: [record,...]` or `record: record`, optionally `checkpoint: {source: "generation-qualified-reader", offset: 42}`. The request must be at most 1 MiB and 1000 records. A record has these required fields:

```json
{"schema_version":1,"event_id":"stable-occurrence-id","source_node":"graph","observed_at":"2026-09-22T12:00:00Z","kind":"journal","severity":"INFO","body":{"message":"original approved content","value":2.5},"attributes":{"service.name":"example"}}
```

Optional `occurred_at` preserves original occurrence time, `source_cursor` preserves the source-native occurrence cursor, and `dataset` identifies the semantic family. Approved kinds: monitoring, lifecycle, security, network, audit, journal, application, system, collector. Severity is TRACE, DEBUG, INFO, WARN, ERROR, or FATAL. Body and attributes retain JSON types; nonfinite values, unknown top-level fields, deeply nested structures, foreign source nodes, and conflicting IDs fail admission. Use an opaque stable ID per occurrence, never a raw credential/label fingerprint. Matching replays retain the original obligations. Caller minimization remains required: this contract does not decide whether arbitrary source content is approved for export.

HTTP 202 with `ack: local_fsync` means the whole batch and checkpoint committed to the local WAL with synchronous FULL. It does not mean transport accepted or destination indexed. HTTP 409 means conflicting content or a regressing checkpoint; 507 means capacity pressure and retry the unchanged batch; 503 means storage unavailable. None of these errors advance the checkpoint. Do not acknowledge/drop a caller-owned durable outbox until the actual 202 acknowledgement is parsed. After the 24-hour archive expires, event-ID dedup history also expires; sources must use persistent generation offsets/reconciliation watermarks.

Ingress bearer-token files contain the raw token. Sink auth files contain the complete Authorization value (`Bearer ...`, `ApiKey ...`, or `Basic ...`), with separate write/read identities. All must be private regular files, mode 0600 or stricter; symlinks are refused. Secrets never appear in CLI arguments, exceptions, or worker output. Loopback HTTP is intended only behind an authenticated owner-local Serve/TLS proxy. Nonloopback ingress requires an explicit private address plus `tls_cert_file` and `tls_key_file`. Destination HTTPS always verifies CA and hostname; redirects and environment HTTP proxies are disabled. Malcolm TLS can use the optional client certificate/key.

`GET /metrics` uses the same ingress authentication and returns aggregate Prometheus gauges for records, pending/archive charge and obligation states. `status` includes retries per destination. Scrape these through the owning collector and monitor collector `otelcol_exporter_enqueue_failed_*`/queue metrics. Do not feed this runtime's raw logs back into itself.

Quota accounting reserves payload plus per-record/per-obligation metadata against 4 GiB pending and 8 GiB archive. At the final successful readback, archive charging and final obligation verification happen in one transaction; insufficient archive capacity leaves the last obligation pending. Archive retention is at least 24 hours after every admission-time sink verifies; no pressure-based early eviction. Admission checks an additional 2 GiB filesystem floor plus conservative WAL/page amplification. Actual disk space includes SQLite indexes/pages/WAL and native metric queues; the resolved deployment must enforce the same floor across writers with its filesystem guardian and measured physical headroom. This local spool cannot survive destruction of its disk.

Elastic uses native JSON bulk indexing into a regular fixed index with source-node-prefixed IDs and `_search` readback. Install `elastic-logs-template.json` through the owner before sending: disabled indexing of the nested `lme` object preserves arbitrary approved typed content in `_source`. HertzBeat 1.9 uses OTLP JSON logs `/api/otlp/v1/logs` and its real paginated GET `/api/observability/logs` query. It stores canonical JSON in the native log body. Malcolm sends newline JSON over verified TLS port 5045 and reads `/mapi/document` with `doctype: host`; host-log parsing must preserve the nested `lme` object. A socket write never verifies storage. HB/Malcolm retries can index duplicates; canonical IDs permit reconciliation. Returned payload content, not a copied digest, controls final verification.

Native metrics use `otel-metrics.example.yaml`, never this log endpoint. The two permanent local OTLP HTTP routes are `127.0.0.1:14318/v1/metrics` (Elastic) and `127.0.0.1:14319/v1/metrics` (Elastic + HertzBeat). Keep both routes while old source outbox obligations remain. HertzBeat-origin samples use the Elastic-only route to avoid a loop back into their originating native history. Generic OTel-owned metric families use the selected route. Each exporter has a 256 MiB persistent byte-sized queue; queue admission is distinct from readback. Collector queues may discard permanent export errors, so a source-native verified outbox must retain its copy until query verification. Provision `elastic-metrics-template.json` with the installed ES 8.18 `metrics@mappings` component, and qualify actual sample queries. No automatic provisioning or credential distribution is performed by these templates.

Native HertzBeat metric retirement: `python3 -m lme_telemetry --config FILE verify-native-metrics --outbox-dir /var/lib/hertzbeat/native-metrics` reads the source-owned version-1 `UUID.accepted` binary envelopes and queries `native_metrics.elastic` (same HTTPS/auth schema as an Elastic log sink, index `lme-native-metrics`). It writes fsynced content receipts `readbacks/UUID.elastic.json` for Java's verified outbox consumer; it never deletes the native source file. The source embeds bounded `lme.metric.unit`, `lme.metric.type`, and `lme.scope.name` metadata as native metric attributes. Each native gauge's name, double value, nanosecond timestamp, unit, scope, resource attributes, and point dimensions must match actual queried `_source`. No metadata may be filled from a digest. Unsupported signal shapes and absent/mismatched fields remain pending. The metrics template uses date_nanos, keyword dimensions, and the named ES8.18 metric dynamic mappings so nanoseconds and exact dimension lookups survive storage. This receipt command handles the HB-origin Elastic mirror; it does not falsely qualify HB native history or generic OTel histograms through that gauge contract.
