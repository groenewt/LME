# Native collector detection probe

The role installs `native_probe.py` alongside reconciliation. Invoke it as the HertzBeat owner with `python3 /data/lmehertzbeat/hertzbeat/native_probe.py --config PRIVATE_JSON`. This executes actual native API detection on exact already reconciled IDs; it does not create or alter monitors.

Configuration contains `run_id`, `deadline_seconds` (1–600), `api` (`origin`, CA file `ca_file`, full Basic/Bearer header file `authorization_file`), and 1–128 `monitors`. Each monitor requires native numeric `id`, UUID `service_id` and `revision`, canonical `source_id`, exact `app`, `host`, and `port`; SSH also requires its forced-command UUID `service_token`. The supported apps are `lme-service-ssh`, `lme-elasticsearch-rest`, and `lme-elasticsearch-jmx`. Default expectation is `detect_success`. An explicitly prepared owned negative fixture uses `expect: detect_failed` and `failure_category` of `ssh_host_key`, `certificate`, `hostname`, or `authentication`. The probe does not itself alter keys, credentials, server certificates, or destinations to create negative fixtures.

Before issuing any detection request, the command retrieves every deployed native template and verifies its qualified source SHA-256, then retrieves each native monitor DTO and checks current run, source, managed ownership, service ID, revision, exact endpoint, and required authentication parameters. It submits the unchanged stored destination and masked credential fields to `/api/monitor/detect`; the native server restores credentials against the matching persisted monitor. A success requires the actual native detection success status/code/message. A negative fixture requires actual collector failure code 2 and the expected sanitized failure category; configuration validation failure code 1, timeout, and generic health success cannot satisfy it.

The single JSON result has `schema_version: 1`, `kind: hertzbeat-native-detect`, run and wall-clock timestamps, aggregate `passed`, and `results`. Each observation carries native monitor/source/template identity, exact target, `native_detect` status/code/sanitized category, and actual API-channel TLS version/cipher/peer certificate digest. Native detection only executes the priority-zero metric group. Its API returns neither sample values nor the collector connection's negotiated TLS/cipher/SSH host key; `collector_negotiated_transport` and `sample_fields` are explicitly null. Acceptance must independently query native history for original samples and qualify the actual patched artifact. API-channel TLS fields do not prove collector TLS negotiation. Exit codes are 0 for matching observations, 1 for observed mismatches, and 2 for structural/transport failure; exception text and raw secret-bearing native errors are never emitted.

`python3 -m unittest discover -s config/hertzbeat-platform -p test_native_probe.py -v` runs nine real localhost HTTPS boundary tests with synthetic certificates/API responses. These tests are regression evidence only, not live HertzBeat acceptance.
